Dienstleistung - the commonest public-sector page type, and the one every municipality currently re-solves locally. Section order and wording follow the FIM Baustein Leistungen, which is what makes two authorities describe the same service the same way; the same order is what service.berlin.de renders. Composed entirely from existing components. The section labels are fixed and translated rather than editable: a visitor moving between two municipalities should meet the same words in the same order, which is the whole point of standardising them. Short facts are headed statements, not a description list. That is how Berlin renders them ("Gebühren: keine"), and it avoids a fourth hand-written copy of the kern-description-list markup - molecule.descriptionList takes its items as an array, and Fluid cannot omit a key from an array literal conditionally, so composing it would print an empty
for every fact left blank. The long parts are open headed sections, not accordions. A Dienstleistung is a legal text people search with Ctrl+F, and details/summary hides its body from find-in-page; the toc block cannot reach inside a single block either, so folding them away would remove them from the only in-page navigation there is. Link fields are resolved to a URI first and every guard tests that string. A Content Blocks Link field is a TypolinkParameter object, and an object is truthy in Fluid even when the editor left it empty - guarding on the field would render the call-to-action button with an empty href. Every section is wrapped in its own f:if so an unfilled field emits no wrapper at all, the rule molecule.alert records for its body.
