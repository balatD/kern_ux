The confirmation step, rendered with KERN's summary component. Each entered value gets its key and value from the element label and the submitted data - a confirmation page that shows raw field identifiers defeats its own purpose. formvh:renderAllFormValues is the only way to reach the values: it walks every element of every *previous* page and yields a formValue per element. Iterating a variable of our own would silently render nothing, because Fluid resolves an unknown variable to null and f:for over null is a no-op rather than an error. One dl per row, not one dl around all rows. The rows have to be siblings of the section headers - a heading is not a permitted child of dl - and kern-summary__body is itself a flex column, so it lays the sequence out. kernt3.css tightens its gap back down for these lists. A Fieldset becomes a section: KERN has kern-summary-group__header for exactly this, including a :first-of-type margin reset, so a form grouped into "Persönliche Daten" and "Anliegen" reads as two blocks rather than one flat list.
