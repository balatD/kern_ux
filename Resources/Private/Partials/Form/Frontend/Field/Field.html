The KERN field row. Every kern-form-input control goes through here, which is the point: KERN's form contract has several parts that are individually easy to forget, and forgetting any one of them is an accessibility defect rather than a cosmetic one. DOM order is label, hint, control, error - that is the order KERN prescribes, and it is also the order a screen reader reads. The optional marker is inverted on purpose: KERN marks the optional minority and leaves required fields unmarked, the opposite of ext:form's own convention. The field is still announced as required, via aria-required on the control itself (see kux:formFieldAttributes). kernUxPrefix and kernUxSuffix put a unit next to the control ("EUR", "km"). Text only, and always announced: an addon is a string somebody typed into the form definition, so if it should not reach a screen reader the answer is not to type it. That is why there is no "decorative" flag and no aria-hidden branch here - kux:formFieldAttributes points aria-describedby at these spans unconditionally.
