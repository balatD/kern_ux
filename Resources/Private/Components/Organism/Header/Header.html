KERN ships no header component, only a grid pattern, so this is ours (kernt3-). Two bands from the navigation breakpoint up, which is what KERN's own example and the Dachmarke reference both show: the brand and the service links share one row, the main navigation has the row below. An earlier version gave the service links a row of their own, which made three bands out of what should be two and pushed the content down for nothing. Below that breakpoint there is no room for two bands, so both navigations are one collapsible panel instead - main navigation first, service links under a divider after it. The panel is what puts them in that order: document order is the mobile order, so the screen reader and the tab sequence follow what is on screen, and desktop is the case that reorders (via grid areas), not mobile. Keeping the service links in the top bar and only hiding them was what put them beside the burger button on a phone. Both mobile toggles carry aria-expanded and aria-controls, and navigation.js keeps those in sync with the class that hides the panel.
The Kopfzeile renders inside this header rather than above it, and that is an accessibility requirement rather than a layout choice. On its own it was page content outside every landmark, which axe reports as `region`; giving it a
or role="banner" of its own would instead make a second banner landmark on the page. It belongs to the page banner, so it lives in the one that exists. One container for the whole header, so every band lines up on the same edges and the desktop grid can place the bands as areas of it.
{siteTitle} The toggles only exist below the navigation breakpoint. They are in the markup unconditionally and hidden in CSS rather than the other way round: a control that appears only after JavaScript has run is a control a keyboard user can reach before it works.
No autocomplete attribute: "search" is not a valid autofill token, and WCAG 1.3.5 only covers fields collecting information *about the user* - a site search box does not. KERN's own header example uses autocomplete="search", which axe correctly flags; not copied.
The panel is what the burger button opens: one box holding both navigations, so they collapse and scroll as a unit instead of the service links reappearing up in the top bar. On desktop it is display:contents, which hands both navigations straight to the header grid - so the wrapper costs nothing there. The main navigation list is molecule.navigationList, which renders itself per level - so the depth follows the menu configuration rather than the number of loops here.
