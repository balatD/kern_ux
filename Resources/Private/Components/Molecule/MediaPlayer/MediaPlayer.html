KERN has no media component, so this is ours (kernt3-). Deliberately the native player with `controls`: a custom player means rebuilding keyboard operation, focus handling and screen-reader labelling for every control, and browsers already ship all of it correctly. Audio description has two routes here, and that is not redundancy. A descriptions track is the tidy answer and the one almost nothing implements: browsers parse kind="descriptions" and then do nothing with it - no speech, no exposure to assistive technology. Shipped anyway because it costs one element and is what a player that does implement it would read. What satisfies WCAG 1.2.3 and 1.2.5 today is a second cut of the video whose soundtrack describes the picture, offered as a link. Unglamorous, and it works in every browser. Takes URLs rather than FAL objects - the content block does that mapping, so this component stays independent of where a file is managed.
