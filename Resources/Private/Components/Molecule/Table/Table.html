The scroll container is not decoration. A table that overflows has to be reachable by keyboard, so the wrapper carries tabindex="0" - this is byte-for-byte what lib.kernUx.rte injects around an editor-drawn table in setup.typoscript, so the two paths cannot drift apart and axe's scrollable-region-focusable holds for both. No class on thead. KERN defines __body, __row, __header, __cell and __footer and nothing for the head; adding a kern-table__head would be inventing a class. The caption is a kern-title because KERN styles it as one: `.kern-table .kern-title { display: table-caption }`. That it may also be visually hidden is anticipated upstream - `.kern-sr-only:not(caption)` exists precisely so a hidden caption keeps its place in the table box instead of being pulled out of it. Cells go through f:format.nl2br in tag form, which escapes its children and only emits the
itself, so the wizard's in-cell line breaks survive without f:format.raw handing an editor a way to write markup into the page.
