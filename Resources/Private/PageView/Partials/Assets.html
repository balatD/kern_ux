Asset inclusion lives in Fluid rather than TypoScript so the boolean site settings stay booleans. TypoScript constant substitution would flatten them into strings and force conditions around every include. rte.css carries KERN's typography for rich text, scoped to the .kernt3-rte wrapper every block puts around a parsed field. The editing view gets the same rules from rte-editor.css, which only the RTE preset loads. The project's own stylesheet, last so it can override without the project having to replace the set. One setting rather than a build step: a project that has a build already knows where to put its output, and one that does not should not need one to change a colour. Icons. Emitted here rather than through page.shortcutIcon because these are site settings, and a TypoScript constant would flatten an unset one into the string "0" - which is a path, so the browser would request it. Each is optional and independent: an SVG icon covers every size where it is supported, the .ico is what a browser asks for at /favicon.ico regardless, and the other two only matter to a site that wants to be installed.
