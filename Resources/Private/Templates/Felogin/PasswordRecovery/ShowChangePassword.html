Step two of the password recovery: set the new password. The requirements are the hint of the first field rather than a list below the form. KERN puts constraints before the control because that is where somebody filling in a form reads them, and the aria-describedby means a screen reader hears them before typing rather than after failing. Core shows this sentence only when there are requirements to explain, and that condition is kept: without any, "enter your new password twice" is already what the two labelled fields say.
  • {passwordRequirement}
    •      Hint first, then the error - the order KERN puts them in the DOM, and the order they should be read in. false rather than an empty string where neither applies: Fluid's tag builder drops a false attribute and renders aria-describedby="" for an empty one, which points at nothing.
